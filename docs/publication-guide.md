# 知识库回答引用校验与证据追溯

知识库回答中的引用标记经常给审核人一种“已经有依据”的印象，但来源存在、引文真实、版本有效、权限正确和语义支持，是不同的判断。回答可能引用已撤回制度、把两个版本混在一起、用错误数字概括原文，甚至提供根本不存在的引文。

本能力把回答组织为可逐条检查的声明，建立“声明 → 来源 → 固定版本 → 原文范围 → 检查发现 → 发布决策”的证据路径，帮助业务系统在回答进入发布流程前分流需要复核或阻断的内容。

| 业务能力 | 实际行为 |
| --- | --- |
| 固定来源与版本校验 | 不存在的版本不自动回退；新旧版本混用给出复核提示。 |
| 引文精确定位 | 严格校验引文是否真实存在于版本正文，返回可高亮范围；重复引文不猜位置。 |
| 时效与撤回 | 检查版本生效、到期和文档/版本撤回，区分复核与阻断。 |
| 来源范围控制 | 按可信租户与来源许可列表限制查找；不可用来源不回传标题、正文、版本或引文。 |
| 必引声明覆盖 | 缺少必须引用的声明会阻断；必引策略由服务端规则决定。 |
| 数字检查提示 | 对比声明与可用引文的数字标记，缺失时转交复核；不把它当作数值语义验证。 |
| 审计导出 | 保存逐条发现、可访问版本正文和原文锚点，便于人工检查与后端留档。 |

内置中文“引证台”可切换完整引用、伪造引文、来源过期、跨租户引用、版本混用、数值待核对和文档撤回场景。点击声明即可查看对应原文高亮与检查路径。

交付包括零运行时依赖 TypeScript 核心、ESM 与类型声明、静态演示、21 项领域测试、完整 README 和四栏发布材料。所有演示机构、规则及文档均为虚构；没有调用模型、真实知识库或外部服务。

**结构校验通过不等于回答正确。** 本能力不执行事实核验、语义蕴含判断、根因分析或通用幻觉检测，真实内容审核仍需人工或独立的语义审核流程。


### 平台栏目：技术要点

# 技术要点

## 明确的输入输出合同

输入包括回答 ID、可信租户、来源许可列表、固定版本注册表、逐条声明与引用、确定性检查时点。`auditAnswer()` 返回 `pass / review / block`、逐引用发现、覆盖统计、版本混用信息和授权证据快照。决策遵循 `block > review > pass`。

来源身份为租户加 sourceId；同一来源内版本 ID 唯一，当前版本指针须有效。声明 ID 唯一。先验证可信注册表结构，再限制到本租户且被允许的来源，随后检查固定版本与正文。

不可访问来源和不存在的来源统一返回 `SOURCE_UNAVAILABLE`，不通过差异错误泄露存在性，也不把来源标题、版本、正文或引文写入结果。但输入声明文本是调用方已经提供的回答，会被保留；本能力不是回答脱敏或输出 DLP 系统。

## 精确锚点与 Unicode 边界

锚点使用 JavaScript **UTF-16 code unit、0 基、终点排他 `[start,end)`**，不等同于字节、Unicode code point 或用户感知字符。例如 emoji 通常占两个 code unit，起止范围不允许切开代理对；组合字符的字素簇边界不在当前校验范围内。

不进行空白折叠、Unicode 归一化、OCR 修复或省略号补写。没有显式范围时，唯一精确匹配会自动定位；多处出现则要求补范围。引用必须来自正文，标题不能冒充正文。

当前使用自有协议，没有实现模型供应商 citation 或 PDF 页码适配器。外部偏移协议必须在适配层转换，并与不可变文本提取版本一起验证。

## 版本、时效与决策

时间使用 Unix 毫秒。有效区间为 `[validFrom,validUntil)`；未生效、已撤回、引用不匹配、无访问范围或必引缺失会阻断。过期、非当前版本、多版本混用或数字标记缺失要求复核。

覆盖表示存在唯一锚定且未被阻断的引用，不等于可以发布。过期来源可同时“有锚点”和“需复核”。同一声明即便还有一个有效引用，只要另一个引用被阻断，整条声明和整个回答仍然阻断。

## 数字检查与语义边界

数字粗检只匹配字面标记，不理解中文数字、单位、否定、范围、计算或指标口径。原文“包含4次巡检”与回答“不包含4次巡检”可能结构通过。测试明确覆盖这一限制，避免把引用定位包装成事实核验。

## 可复用性与可信边界

核心是无状态纯函数，无模型、网络和运行时依赖。检查时点显式注入，结果可复现。`exportAudit()` 只将审计对象序列化为 JSON，本身不是额外脱敏器，必须传入未被追加秘密字段的 `auditAnswer()` 结果。

`requiresCitation`、租户与许可列表必须由服务端策略产生，不能信任模型或不可信客户端自报。当前返回授权版本的完整正文，尚未做内容体积控制、流式处理、加密持久化或生产发布网关；这些应在业务接入层完成。


### 平台栏目：应用场景

# 应用场景

## 企业知识库回答发布前复核

客服或内部助手根据制度文档生成回答后，将需证据的业务结论拆成声明，固定引用版本与原文。审核台先拦截伪造引文、缺失版本和撤回文档，再把过期、数值差异或新旧版本混用交给人工核查。

该流程适合“确认引用真实且可追溯”的检查，不取代回答的语义正确性判断。

## 多租户知识库的证据输出约束

同一知识服务管理多个租户文档时，由服务端按当前会话提供租户与允许来源。不可访问的引用只得到统一不可用结论，不能借证据详情或审计导出返回另一租户的文档标题与正文。

生产服务应在后端执行，并避免把未授权文档下发浏览器。演示前端注册表全部是虚构数据，用来验证输出规则，不代表浏览器隐藏具有保密能力。

## 制度版本升级后的历史回答排查

当服务手册、售后规则或内部知识更新时，用相同检查时点和版本注册表重跑既有回答，定位引用旧版、到期或撤回内容的声明。结果可交给人工决定是否更新回答或保留历史适用说明。

版本混用只表示同一回答引用了多个版本，不声称两个版本已经发生语义冲突。业务方需解释版本适用范围和过渡期。

## 生成式问答的离线回归检查

使用固定虚构输入，复现引文伪造、重复引文消歧、emoji 范围、权限边界、过期时点与数字提示，避免接口升级后引用定位行为悄然改变。

不覆盖模型效果评估、真实权限服务验收、对抗性提示注入检测或生产吞吐测试。

## 正式接入需配合的内容

- 可信认证与来源 ACL、服务端必引规则，避免模型用 `requiresCitation: false` 绕过检查。
- 不可变文档版本、文本提取记录与原件哈希，确保锚点与审计时文本一致。
- 回答拆分、检索与模型接入；本包不包含这些流程。
- 审计持久化、人工复核结果及真实发布网关，阻断不能只停留在前端提示。
- 输入规模限制、敏感信息检查和独立语义审核，弥补结构校验边界。

# 使用方法

## 获取源码并运行

公开源码仓库：[ai-business-capabilities](https://github.com/XuCheri/ai-business-capabilities)。本能力位于 `evidence-trace/`，完整数据合同和可运行接入示例见该目录 README。

```bash
git clone https://github.com/XuCheri/ai-business-capabilities.git
cd ai-business-capabilities/evidence-trace
npm ci
npm test
npm run demo
```

使用 Node.js 18+，打开 `http://127.0.0.1:5177/demo/`。服务仅绑定本机，按 Ctrl+C 停止。

## 体验审阅流程

1. 选择“完整引用”，查看三条业务声明与对应的有效原文高亮。
2. 选择“伪造引文”，观察第一条声明被阻断，文档里没有对应原句。
3. 选择“来源过期”，原文仍能定位，但决策改为需要复核。
4. 选择“跨租户引用”，再点击第三条声明；详情不返回目标来源的标题、版本或正文。
5. 选择“版本混用”“数值待核对”或“文档撤回”，查看逐条发现与处理理由。
6. 点击“导出审计记录”，下载本次审计 JSON。导出包含授权文档正文，应按业务数据保护规则保存。

所有数据均为虚构；切换场景会重新计算，不会发布回答或修改远端系统。

## 接入领域 API

```js
import { auditAnswer, exportAudit } from './dist/index.js';

const quote = '企业套餐每年包含4次上门巡检。';
const report = auditAnswer({
  answerId: 'demo-answer', tenantId: 'demo-tenant', at: 1000,
  allowedSourceIds: ['demo-document'],
  sources: [{
    id: 'demo-document', tenantId: 'demo-tenant', title: '虚构服务手册',
    currentVersionId: 'v1', versions: [{ id: 'v1', text: quote }],
  }],
  claims: [{
    id: 'claim-1', text: quote, requiresCitation: true,
    citations: [{ sourceId: 'demo-document', versionId: 'v1', quote }],
  }],
});
console.log(report.decision); // pass：结构检查通过，不代表事实正确
console.log(exportAudit(report));
```

先执行 `npm run build`，把示例保存到能力目录内的 `example.mjs`，运行 `node example.mjs`。npm 包未单独发布，可通过仓库源码、构建产物或本地包接入。

`auditAnswer` 接收完整输入；`exportAudit` 仅序列化返回对象，不是对任意对象再次脱敏。不要把原始请求或未授权文档附加到导出结果。

输入中的 `tenantId`、`allowedSourceIds` 和 `requiresCitation` 必须由可信服务端规则产生。源文档版本正文保持不可变；显式锚点采用 UTF-16 code unit `[start,end)`，不能直接套用 PDF 页码或其他引用协议。

## AI 工具调用风险预检与审批门控

### 平台栏目：能力描述

## 让 AI 的业务动作先经过许可，再进入执行

AI 助手能检索知识、生成外发邮件、批量修改设备状态，但“模型想这样做”不等于“当前人员有权这样做”。一次人工批准也不应该在参数变化、角色撤销或重复调用后继续有效。

「AI 工具调用风险预检与审批门控」提供一套可嵌入现有 Agent 调用链的业务组件，把受控工具目录、参数验证、租户与角色范围、人工审批和一次性消费连接起来。核心为零运行时依赖的 TypeScript / ESM 库，并提供中文交互演示、完整源码、28 项自动化测试、可运行接入示例和文档。

### 业务能力

| 能力 | 行为 |
| --- | --- |
| 可信风险预检 | 风险来自应用维护者配置的工具目录，拒绝未知工具，不接受模型自报安全等级 |
| 参数与业务范围 | 严格检查类型、必填、未知字段、数量与枚举，核对主体角色与租户字段 |
| 规则优先级 | 固定拒绝优先于审批、审批优先于直接放行，不受规则排列顺序影响 |
| 人工审批 | 写入、外发与破坏性动作至少需要同租户、具备角色、且不是申请人的审批人 |
| 审批绑定 | 绑定完整规范化参数、工具及版本、主体/租户/角色、策略版本与原到期时间 |
| 一次性许可 | 消费前重新验证当前权限与草稿；改参、过期、换策略或二次消费均拒绝 |
| 可复核审计 | 保存主体标识、状态和机器原因码，隐藏敏感预览，不记录原始参数与正文 |

### 可直接体验的业务场景

中文演示内置内部知识检索、外部邮件发送、批量设备变更和未知工具四个场景。可切换审批身份、修改已批准参数、撤销当前角色、快进时钟、更新策略版本，并导出脱敏审计 JSON。

所有演示数据均为虚构样例；“模拟执行”只表示许可被消费，不会发送真实邮件或修改设备。项目是单实例内存参考实现，不是生产安全网关。正式接入需补充认证、持久化、资源级授权、事务与下游幂等执行。

### 平台栏目：技术要点

## 1. 风险由受控目录决定

工具注册信息由可信应用维护者配置，包括工具 ID、版本、风险、参数约定、申请/审批角色、租户参数路径和可选租户范围。模型只提供工具 ID 与参数，不能通过参数字段降低风险。

读取类工具默认可直接放行；写入、外发和破坏性工具始终保留人工审批基线。策略规则可按工具、风险、角色、参数值或批量数量增加限制，多规则命中固定使用 deny > approval-required > allow。

## 2. 参数验证与规范化绑定

参数采用项目自定义的 ArgumentSchema 子集，支持对象、数组、字符串、数值、整数、布尔、必填字段、枚举、上下限；对象始终拒绝未声明字段。这不是完整 JSON Schema 或 MCP 协议校验器。

严格 JSON 处理会拒绝循环、非普通对象、危险原型字段、访问器、稀疏数组、非有限数值等结构，并限制 16 层、10,000 节点与 128 KiB。调用最外层也只接受 toolId、args 数据字段，避免访问器在检查中切换工具身份。

规范化时对象键排序、数组顺序保留。审批绑定完整参数字符串以及工具 ID/版本、策略版本、主体 ID/租户/角色、原始到期时间；使用精确等值校验，不依赖客户端可改的短摘要。参数字段顺序变化不影响绑定，深层内容、数组顺序和身份变化会触发拒绝。

## 3. 有边界的审批状态机

状态流为 allow / deny / approval-required，人工审批可将待审批转为 approved 或 rejected，合法消费转 consumed，过期或策略更新转 expired。

审批人必须同租户、具备该工具的审批角色，且与申请人不同。批准不会延长有效期；拒绝、消费和失效均不能原地恢复。消费时重新验证当前角色、租户与策略，防止审批后权限变化仍被使用。

## 4. 同步一次性消费与参数快照

消费操作在同一个同步调用中完成校验和 consumed 标记，中间没有 await 或外部副作用，保证当前单实例内不能重复取得许可。返回参数经过冻结，下游应执行该确切快照，避免检查后重新读取可变草稿。

这不等于跨进程、跨实例或下游业务的恰好执行一次。生产需数据库事务、唯一消费约束、幂等键、执行结果存储和可靠恢复；真实工具失败也不会自动撤销已消费状态。

## 5. 审计与验证

审计只保留事件时间、请求/工具/主体/租户标识、策略版本、状态与原因码，不写正文、原始参数或任意自由文本备注。敏感预览按 schema 标记与常见凭据字段名隐藏；实际业务需补齐敏感字段定义。

28 项自动化测试覆盖规则顺序、工具风险、深层参数、跨租户、自批、改参、当前角色撤销、精确到期、策略更新、一次性竞争消费、访问器回归和脱敏日志。类型检查、核心构建、静态演示打包及带断言的接入示例已验证。

身份与租户标识仍属于需保护的业务数据。组件不提供登录、鉴权服务、持久化、防篡改日志、资源真实归属查询或下游网络安全控制。


### 平台栏目：应用场景

## 企业 AI 助手的外发动作审批

当助手准备向合作方发送通知、工单摘要或安排确认时，可以先核对固定收件人范围、申请角色与租户，再把具体调用交由另一位审批人确认。

审批只绑定本次收件人与正文。若模型重写内容或用户修改草稿，需要重新预检；原批准不能被当作对后续所有邮件的授权。演示以虚构邮箱展示流程，不实际发信。

## 运维 Agent 的批量变更门控

设备状态、巡检任务、工单分派等批量变更，可以先检查变更数量和目标动作。演示规则对超过 20 台设备或禁用设备的请求直接拒绝，其余写操作仍要求人工审批。

此类门控用于减少模型提议超出业务范围的动作。真实设备归属、资源级权限与变更执行仍由后端校验，不能仅凭参数中写了正确租户就信任全部资源 ID。

## 内部知识工具与业务操作分级

同一助手往往同时拥有只读检索和业务写入工具。受控工具目录可让正常读取直接获得一次性许可，同时把外发、写入或破坏性调用纳入独立审批。

未知工具即使声称自己是“只读”也不会自动被注册。工具更新时使用明确版本，策略更新时使原未消费许可失效，避免旧批准被新规则误用。

## AI 业务流程验证与评审

在接入真实工具前，团队可以通过演示验证权限口径：谁能申请、谁能批准、能否自批、如何处理跨租户、参数修改、到期、角色撤销与重复执行。

脱敏审计 JSON 可用于检查状态变化和拒绝原因。它是应用内事件记录，不是防篡改证据，也不代表下游动作已经实际完成。

## 适用边界

适合内部 Agent 原型、审批业务验证与已有服务端工具门控的参考实现。高影响生产动作必须把门控放在唯一执行入口，由可信后端提供身份、权限、事务、持久化和幂等机制。本项目不提供可跨机器离线验证的签名票据，也不替代下游资源授权。

## 一、获取与运行

准备 Node.js 20.19+，执行：

```bash
git clone https://github.com/XuCheri/ai-business-capabilities.git
cd ai-business-capabilities/action-gate
npm ci
npm run check
npm test
npm run demo
```

浏览器打开 `http://127.0.0.1:5188`。首次安装开发依赖需要联网，演示不连接模型或业务后端。ES Modules 需通过 HTTP 加载，不建议直接双击 HTML。停止服务使用 Ctrl+C。

## 二、推荐体验流程

1. 外部邮件场景：运行预检，检查需要审批，切换同租户审批人批准，再消费一次许可。
2. 重复点击消费，观察 ALREADY_CONSUMED 拒绝。
3. 新建预检并批准后修改参数，再消费，观察 BINDING_MISMATCH。
4. 将审批人切换为申请人、其他租户或无审批角色人员，验证拒绝原因。
5. 载入 32 条批量设备变更，预检命中数量规则直接拒绝。
6. 快进 11 分钟或更新策略版本，验证尚未消费许可失效。
7. 在消费时切换为 operator 角色已撤销的主体，验证当前权限重新检查。
8. 导出脱敏审计 JSON，查看预检、批准、拒绝和消费记录。

演示的执行结果均标注“模拟执行”，不会真的发送邮件、调用模型或变更设备。

## 三、集成到现有调用链

```text
模型提出 toolId + args
→ 服务端读取可信 Principal
→ preflight 风险预检
→ 如需审批，独立身份调用 approve / reject
→ 唯一执行入口调用 consume 再次校验
→ 固定适配器执行返回的冻结 args
```

| API | 用途 |
| --- | --- |
| new ActionGate | 注册受控工具、版本策略，可注入时钟与 ID 生成器 |
| preflight(call, principal) | 校验参数、主体/租户与规则，返回决策记录 |
| approve / reject | 对待审批记录执行合法身份的人工决策 |
| consume(id, call, principal) | 核对原绑定和当前权限，返回一次性执行许可 |
| inspect / list / audit | 可信后端查看状态和脱敏记录 |
| replacePolicy | 使用新版本策略，使旧未消费许可失效 |

包内 README 提供完整工具注册和可复制运行的示例。另可执行 `npm run build && node examples/basic.mjs`，验证改参拒绝、正常消费、二次消费与精确到期边界。`npm run demo:build` 生成可部署到 HTTP 静态站点的 demo-dist。

## 四、生产接入要求

- 工具目录、策略和 Principal 来自可信后端，不能从模型文本或前端可修改角色字段直接建立授权。
- 审批界面应展示准确的原始业务内容；脱敏 preview 不能单独替代审核所需正文。
- consume 必须成为真实工具的唯一执行路径，执行返回的冻结参数快照，不能绕开或改用旧草稿。
- 单实例同步消费不保证跨实例或下游恰好执行一次，需事务、唯一约束、幂等与执行状态持久化。
- 组件只校验声明租户字段与主体一致；具体资源的真实租户归属、URL/网络安全和业务权限仍需下游验证。
- 核心没有后台计时器或网络连接。实例状态保存在内存，重启会丢失；生产需控制日志保留、并发与容量。
