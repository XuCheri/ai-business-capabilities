## 一、获取与运行

项目源码：[XuCheri/ai-business-capabilities](https://github.com/XuCheri/ai-business-capabilities)，能力目录为 action-gate。

准备 Node.js 20.19+，执行：

```bash
git clone https://github.com/XuCheri/ai-business-capabilities.git
cd ai-business-capabilities/action-gate
npm ci
npm run check
npm test
npm run demo
```

浏览器打开 `http://127.0.0.1:5188`。首次安装开发依赖需要联网，演示不连接模型或业务后端。ES Modules 需通过 HTTP 加载，不建议直接双击 HTML。停止服务使用 Ctrl+C。

## 二、推荐体验流程

1. 外部邮件场景：运行预检，检查需要审批，切换同租户审批人批准，再消费一次许可。
2. 重复点击消费，观察 ALREADY_CONSUMED 拒绝。
3. 新建预检并批准后修改参数，再消费，观察 BINDING_MISMATCH。
4. 将审批人切换为申请人、其他租户或无审批角色人员，验证拒绝原因。
5. 载入 32 条批量设备变更，预检命中数量规则直接拒绝。
6. 快进 11 分钟或更新策略版本，验证尚未消费许可失效。
7. 在消费时切换为 operator 角色已撤销的主体，验证当前权限重新检查。
8. 导出脱敏审计 JSON，查看预检、批准、拒绝和消费记录。

演示的执行结果均标注“模拟执行”，不会真的发送邮件、调用模型或变更设备。

## 三、集成到现有调用链

```text
模型提出 toolId + args
→ 服务端读取可信 Principal
→ preflight 风险预检
→ 如需审批，独立身份调用 approve / reject
→ 唯一执行入口调用 consume 再次校验
→ 固定适配器执行返回的冻结 args
```

| API | 用途 |
| --- | --- |
| new ActionGate | 注册受控工具、版本策略，可注入时钟与 ID 生成器 |
| preflight(call, principal) | 校验参数、主体/租户与规则，返回决策记录 |
| approve / reject | 对待审批记录执行合法身份的人工决策 |
| consume(id, call, principal) | 核对原绑定和当前权限，返回一次性执行许可 |
| inspect / list / audit | 可信后端查看状态和脱敏记录 |
| replacePolicy | 使用新版本策略，使旧未消费许可失效 |

包内 README 提供完整工具注册和可复制运行的示例。另可执行 `npm run build && node examples/basic.mjs`，验证改参拒绝、正常消费、二次消费与精确到期边界。`npm run demo:build` 生成可部署到 HTTP 静态站点的 demo-dist。

## 四、生产接入要求

- 工具目录、策略和 Principal 来自可信后端，不能从模型文本或前端可修改角色字段直接建立授权。
- 审批界面应展示准确的原始业务内容；脱敏 preview 不能单独替代审核所需正文。
- consume 必须成为真实工具的唯一执行路径，执行返回的冻结参数快照，不能绕开或改用旧草稿。
- 单实例同步消费不保证跨实例或下游恰好执行一次，需事务、唯一约束、幂等与执行状态持久化。
- 组件只校验声明租户字段与主体一致；具体资源的真实租户归属、URL/网络安全和业务权限仍需下游验证。
- 核心没有后台计时器或网络连接。实例状态保存在内存，重启会丢失；生产需控制日志保留、并发与容量。
