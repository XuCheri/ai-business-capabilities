## 让 AI 的业务动作先经过许可，再进入执行

AI 助手能检索知识、生成外发邮件、批量修改设备状态，但“模型想这样做”不等于“当前人员有权这样做”。一次人工批准也不应该在参数变化、角色撤销或重复调用后继续有效。

「AI 工具调用风险预检与审批门控」提供一套可嵌入现有 Agent 调用链的业务组件，把受控工具目录、参数验证、租户与角色范围、人工审批和一次性消费连接起来。核心为零运行时依赖的 TypeScript / ESM 库，并提供中文交互演示、完整源码、28 项自动化测试、可运行接入示例和文档。

### 业务能力

| 能力 | 行为 |
| --- | --- |
| 可信风险预检 | 风险来自应用维护者配置的工具目录，拒绝未知工具，不接受模型自报安全等级 |
| 参数与业务范围 | 严格检查类型、必填、未知字段、数量与枚举，核对主体角色与租户字段 |
| 规则优先级 | 固定拒绝优先于审批、审批优先于直接放行，不受规则排列顺序影响 |
| 人工审批 | 写入、外发与破坏性动作至少需要同租户、具备角色、且不是申请人的审批人 |
| 审批绑定 | 绑定完整规范化参数、工具及版本、主体/租户/角色、策略版本与原到期时间 |
| 一次性许可 | 消费前重新验证当前权限与草稿；改参、过期、换策略或二次消费均拒绝 |
| 可复核审计 | 保存主体标识、状态和机器原因码，隐藏敏感预览，不记录原始参数与正文 |

### 可直接体验的业务场景

中文演示内置内部知识检索、外部邮件发送、批量设备变更和未知工具四个场景。可切换审批身份、修改已批准参数、撤销当前角色、快进时钟、更新策略版本，并导出脱敏审计 JSON。

所有演示数据均为虚构样例；“模拟执行”只表示许可被消费，不会发送真实邮件或修改设备。项目是单实例内存参考实现，不是生产安全网关。正式接入需补充认证、持久化、资源级授权、事务与下游幂等执行。
