# 使用方法

## 获取源码并运行

公开源码仓库：[ai-business-capabilities](https://github.com/XuCheri/ai-business-capabilities)。本能力位于 `evidence-trace/`，完整数据合同和可运行接入示例见该目录 README。

```bash
git clone https://github.com/XuCheri/ai-business-capabilities.git
cd ai-business-capabilities/evidence-trace
npm ci
npm test
npm run demo
```

使用 Node.js 18+，打开 `http://127.0.0.1:5177/demo/`。服务仅绑定本机，按 Ctrl+C 停止。

## 体验审阅流程

1. 选择“完整引用”，查看三条业务声明与对应的有效原文高亮。
2. 选择“伪造引文”，观察第一条声明被阻断，文档里没有对应原句。
3. 选择“来源过期”，原文仍能定位，但决策改为需要复核。
4. 选择“跨租户引用”，再点击第三条声明；详情不返回目标来源的标题、版本或正文。
5. 选择“版本混用”“数值待核对”或“文档撤回”，查看逐条发现与处理理由。
6. 点击“导出审计记录”，下载本次审计 JSON。导出包含授权文档正文，应按业务数据保护规则保存。

所有数据均为虚构；切换场景会重新计算，不会发布回答或修改远端系统。

## 接入领域 API

```js
import { auditAnswer, exportAudit } from './dist/index.js';

const quote = '企业套餐每年包含4次上门巡检。';
const report = auditAnswer({
  answerId: 'demo-answer', tenantId: 'demo-tenant', at: 1000,
  allowedSourceIds: ['demo-document'],
  sources: [{
    id: 'demo-document', tenantId: 'demo-tenant', title: '虚构服务手册',
    currentVersionId: 'v1', versions: [{ id: 'v1', text: quote }],
  }],
  claims: [{
    id: 'claim-1', text: quote, requiresCitation: true,
    citations: [{ sourceId: 'demo-document', versionId: 'v1', quote }],
  }],
});
console.log(report.decision); // pass：结构检查通过，不代表事实正确
console.log(exportAudit(report));
```

先执行 `npm run build`，把示例保存到能力目录内的 `example.mjs`，运行 `node example.mjs`。npm 包未单独发布，可通过仓库源码、构建产物或本地包接入。

`auditAnswer` 接收完整输入；`exportAudit` 仅序列化返回对象，不是对任意对象再次脱敏。不要把原始请求或未授权文档附加到导出结果。

输入中的 `tenantId`、`allowedSourceIds` 和 `requiresCitation` 必须由可信服务端规则产生。源文档版本正文保持不可变；显式锚点采用 UTF-16 code unit `[start,end)`，不能直接套用 PDF 页码或其他引用协议。

## 构建与验证

```bash
npm run check
npm test
npm run build
npm run demo:build
```

`dist/` 包含 ESM 与类型声明；`demo-dist/` 为静态演示，需通过 HTTP 静态服务加载 ESM，不承诺 file:// 双击可用。测试覆盖 21 项边界规则。正式接入仍需服务端认证、版本存储、真实发布阻断、审计留存与内容语义复核。
