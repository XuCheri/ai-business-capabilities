# 知识库回答引用校验与证据追溯

知识库回答中的引用标记经常给审核人一种“已经有依据”的印象，但来源存在、引文真实、版本有效、权限正确和语义支持，是不同的判断。回答可能引用已撤回制度、把两个版本混在一起、用错误数字概括原文，甚至提供根本不存在的引文。

本能力把回答组织为可逐条检查的声明，建立“声明 → 来源 → 固定版本 → 原文范围 → 检查发现 → 发布决策”的证据路径，帮助业务系统在回答进入发布流程前分流需要复核或阻断的内容。

| 业务能力 | 实际行为 |
| --- | --- |
| 固定来源与版本校验 | 不存在的版本不自动回退；新旧版本混用给出复核提示。 |
| 引文精确定位 | 严格校验引文是否真实存在于版本正文，返回可高亮范围；重复引文不猜位置。 |
| 时效与撤回 | 检查版本生效、到期和文档/版本撤回，区分复核与阻断。 |
| 来源范围控制 | 按可信租户与来源许可列表限制查找；不可用来源不回传标题、正文、版本或引文。 |
| 必引声明覆盖 | 缺少必须引用的声明会阻断；必引策略由服务端规则决定。 |
| 数字检查提示 | 对比声明与可用引文的数字标记，缺失时转交复核；不把它当作数值语义验证。 |
| 审计导出 | 保存逐条发现、可访问版本正文和原文锚点，便于人工检查与后端留档。 |

内置中文“引证台”可切换完整引用、伪造引文、来源过期、跨租户引用、版本混用、数值待核对和文档撤回场景。点击声明即可查看对应原文高亮与检查路径。

交付包括零运行时依赖 TypeScript 核心、ESM 与类型声明、静态演示、21 项领域测试、完整 README 和四栏发布材料。所有演示机构、规则及文档均为虚构；没有调用模型、真实知识库或外部服务。

**结构校验通过不等于回答正确。** 本能力不执行事实核验、语义蕴含判断、根因分析或通用幻觉检测，真实内容审核仍需人工或独立的语义审核流程。
