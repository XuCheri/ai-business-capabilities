# 技术要点

## 明确的输入输出合同

输入包括回答 ID、可信租户、来源许可列表、固定版本注册表、逐条声明与引用、确定性检查时点。`auditAnswer()` 返回 `pass / review / block`、逐引用发现、覆盖统计、版本混用信息和授权证据快照。决策遵循 `block > review > pass`。

来源身份为租户加 sourceId；同一来源内版本 ID 唯一，当前版本指针须有效。声明 ID 唯一。先验证可信注册表结构，再限制到本租户且被允许的来源，随后检查固定版本与正文。

不可访问来源和不存在的来源统一返回 `SOURCE_UNAVAILABLE`，不通过差异错误泄露存在性，也不把来源标题、版本、正文或引文写入结果。但输入声明文本是调用方已经提供的回答，会被保留；本能力不是回答脱敏或输出 DLP 系统。

## 精确锚点与 Unicode 边界

锚点使用 JavaScript **UTF-16 code unit、0 基、终点排他 `[start,end)`**，不等同于字节、Unicode code point 或用户感知字符。例如 emoji 通常占两个 code unit，起止范围不允许切开代理对；组合字符的字素簇边界不在当前校验范围内。

不进行空白折叠、Unicode 归一化、OCR 修复或省略号补写。没有显式范围时，唯一精确匹配会自动定位；多处出现则要求补范围。引用必须来自正文，标题不能冒充正文。

当前使用自有协议，没有实现模型供应商 citation 或 PDF 页码适配器。外部偏移协议必须在适配层转换，并与不可变文本提取版本一起验证。

## 版本、时效与决策

时间使用 Unix 毫秒。有效区间为 `[validFrom,validUntil)`；未生效、已撤回、引用不匹配、无访问范围或必引缺失会阻断。过期、非当前版本、多版本混用或数字标记缺失要求复核。

覆盖表示存在唯一锚定且未被阻断的引用，不等于可以发布。过期来源可同时“有锚点”和“需复核”。同一声明即便还有一个有效引用，只要另一个引用被阻断，整条声明和整个回答仍然阻断。

## 数字检查与语义边界

数字粗检只匹配字面标记，不理解中文数字、单位、否定、范围、计算或指标口径。原文“包含4次巡检”与回答“不包含4次巡检”可能结构通过。测试明确覆盖这一限制，避免把引用定位包装成事实核验。

## 可复用性与可信边界

核心是无状态纯函数，无模型、网络和运行时依赖。检查时点显式注入，结果可复现。`exportAudit()` 只将审计对象序列化为 JSON，本身不是额外脱敏器，必须传入未被追加秘密字段的 `auditAnswer()` 结果。

`requiresCitation`、租户与许可列表必须由服务端策略产生，不能信任模型或不可信客户端自报。当前返回授权版本的完整正文，尚未做内容体积控制、流式处理、加密持久化或生产发布网关；这些应在业务接入层完成。
